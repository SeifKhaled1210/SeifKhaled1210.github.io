Sailor Online · C++ gameserver
Server-side fixes on a live MMORPG.

    

      

        

          crash fix
          
Unchecked packet length

          
Players could crash the world server by sending a chat packet whose declared length exceeded the buffer. The handler trusted the client's size field and read past the end.

          
Fix

          
Validate the length against what actually arrived before touching the buffer, and drop the session on a malformed packet instead of letting it through.

        


// WorldSession::HandleChatMessage
void HandleChatMessage(Packet& pkt) {
    uint32 len = pkt.ReadU32();
-   std::string msg(pkt.Data(), len);
+   if (len > pkt.Remaining() || len > MAX_CHAT_LEN) {
+       LogWarn("bad chat len %u from %s", len, Addr());
+       KickSession(KICK_MALFORMED);
+       return;
+   }
+   std::string msg(pkt.Data(), len);
    Broadcast(msg);
}

      


      

        

          exploit patch
          
Client-trusted cooldown

          
A skill's cooldown was enforced only in the client. A modified client could spam it every tick, one-shotting bosses. The server just checked mana.

          
Fix

          
Track the last cast time per skill on the server and reject early casts. Small tolerance for latency so honest players never notice.

        


// Player::TryCastSkill
bool TryCastSkill(uint32 skillId) {
    auto& sk = GetSkill(skillId);
    if (mana < sk.cost) return false;
+   uint64 now = ServerTime::Ms();
+   if (now < sk.lastCast + sk.cooldownMs - LATENCY_GRACE_MS)
+       return false;   // early: ignore, don't kick
+   sk.lastCast = now;
    mana -= sk.cost;
    Execute(sk);
    return true;
}

      


      

        

          logic bug
          
Iterator invalidation on death

          
When an AoE killed several mobs at once, some survivors stopped attacking. Killing a mob erased it from the aggro vector while the same loop was iterating it — undefined behaviour that happened to skip the next element.

          
Fix

          
Mark dead entities during the loop, then remove them in one pass afterwards with erase–remove.

        


// AggroTable::Tick
void Tick(float dt) {
-   for (auto it = targets.begin(); it != targets.end(); ++it) {
-       it->Update(dt);
-       if (it->IsDead()) targets.erase(it);  // UB: 'it' now dangling
-   }
+   for (auto& t : targets)
+       t.Update(dt);
+   targets.erase(
+       std::remove_if(targets.begin(), targets.end(),
+                      [](const Target& t){ return t.IsDead(); }),
+       targets.end());
}

          progression bug
          
Offline earnings overflow

          
An idle game computed offline income as rate × seconds in a 32-bit int. Players who left the app for a few days came back to negative gold — and one-star reviews.

          
Fix

          
Compute in double, clamp the offline window to the design cap, and never let a currency go below its previous value.

        


// OfflineProgress.cs
public static long Earned(long rate, DateTime last, DateTime now) {
-   int secs = (int)(now - last).TotalSeconds;
-   return (int)rate * secs;             // overflows past ~24 h
+   double secs = (now - last).TotalSeconds;
+   secs = Math.Clamp(secs, 0, MaxOfflineSeconds);   // design cap: 8 h
+   double earned = rate * secs;
+   return (long)Math.Min(earned, long.MaxValue / 2);
}

      


      

        

          data loss
          
Save corrupted on app kill

          
Android killed the app mid-write and players lost their progress: the save file was written in place, so a half-written JSON was all that remained on next launch.

          
Fix

          
Write to a temp file, flush, then atomically replace the real one. Keep the last good save as a fallback and validate before loading.

        


// SaveSystem.cs
void Write(string json) {
-   File.WriteAllText(SavePath, json);
+   var tmp = SavePath + ".tmp";
+   File.WriteAllText(tmp, json);
+   if (File.Exists(SavePath)) File.Copy(SavePath, SavePath + ".bak", true);
+   File.Replace(tmp, SavePath, null);   // atomic on the platforms we ship
}
string Read() {
+   foreach (var p in new[]{ SavePath, SavePath + ".bak" })
+       if (TryParse(File.ReadAllText(p), out var ok)) return ok;
+   return NewGame();
}

      


      

        

          performance
          
Frame drops from particle spawns

          
Every coin pickup instantiated a new particle prefab and destroyed it a second later. On low-end Android phones the GC spikes showed up as visible stutter in the busiest screens.

          
Fix

          
Pool the effect: pre-warm a handful, reuse, and only grow the pool when it's genuinely empty.

        


// CoinPickup.cs
void OnCollected() {
-   var fx = Instantiate(sparklePrefab, transform.position, Quaternion.identity);
-   Destroy(fx, 1f);
+   var fx = SparklePool.Get();          // pre-warmed, 8 instances
+   fx.transform.position = transform.position;
+   fx.Play();
+   SparklePool.ReturnAfter(fx, 1f);     // disables, doesn't destroy
}

The 20-minute POS freeze
pos_loyalty_guard · gc_loyalty_preload
18.0.2.1.0

        
Cashiers waited 20–30 minutes for the POS to open, and "free product" rewards crashed the screen. A third-party fast-loading module deferred the catalogue, so loyalty rewards loaded with no products to point at, and the repair routine re-read everything on every boot.

        
    
          
  • Guard that detects broken reward↔product links and repairs them at the crash site
    • 
          
  • Then the real fix: preload the ~137 loyalty products into the initial payload (about 1% more data)
    • 
          
  • First attempt overrode the wrong method and silently did nothing — traced the MRO and hooked _load_pos_data after the vendor module
    • 
        

        
0 repairs at startup; POS opens in seconds, vendor modules untouched.
